Everything we build starts from one idea: your writing belongs in plain files you own, and where you publish it should stay your choice. We are building tools for the whole journey, from the first draft to the reader who finds it.

## Projects

### Kite

A Markdown publishing platform. Write in a studio in your browser, keep every post as a Markdown file you own, and publish it as static pages, on your own server, or through Git. Kite is in early development.

[Repository](https://github.com/kite-plus/kite) · [How it works](https://github.com/kite-plus/kite#how-it-works) · [Roadmap](https://github.com/kite-plus/kite#roadmap)

### Explore

A platform for gathering published content and helping readers discover it. Explore is planned and has not launched yet.

## How we build

- **Open formats first.** Content lives in Markdown and Git, so you can read it, diff it, and take it elsewhere without us.
- **Choices you can change.** Where content lives and how it is delivered are separate decisions. Moving hosts should not mean moving tools.
- **Designs in writing.** Architecture is worked out in design documents before code, and a change that conflicts with them updates the documents first.
- **Honest status.** We keep what works today apart from what is planned, in code and in documentation.

## Get involved

- **Try Kite:** follow [Install and start](https://github.com/kite-plus/kite#install-and-start); Docker is the quickest route.
- **Report a bug or share an idea:** open an issue in the project's repository, such as [Kite's issues](https://github.com/kite-plus/kite/issues).
- **Contribute:** each project defines its own contribution notes and license, so start with that project's README.
